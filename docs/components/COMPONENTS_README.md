# Components and screens

The LeadsGhr Tracker toolbar popup matches LeadsGhr Mailer: a small header (logo, name, a refresh button that spins while counts load, and a settings gear), **Track new emails** and **Open notifications** switches, an endpoint set-up notice when needed, a three-number Overview (tracked, opened, image loads), the five most recent emails with ticks and load counts. No tabs and no uppercase section labels. The Gmail details card for a Sent row or message opens to the right of its ticks.

Inside Gmail, the LeadsGhr logo control is placed beside the top-right Settings control. The left navigation has no injected LeadsGhr button. With tracking enabled, Sent rows show a thin SVG double-check mark: both ticks gray by default (including untracked rows), the first tick purple (primary `#5B12C9`) after a confirmed tracked send, and both ticks purple after an image load is observed. Ticks for an email with more than 5 counted loads are followed by a small purple **HOT** chip. Extension settings inputs use the software border colour `#DFD9EC` and a purple border on focus. Messages you sent inside an open conversation show the same ticks beside the message time (class `lg-msg-ticks`; Sent list ticks use `lg-list-ticks`). The ticks are a keyboard-focusable button that opens a floating details card on hover, click, or Enter: the last load as relative time, first load relative to sending, observed-load count, a cache caveat, and no report link. Individual load times are not listed. The popup and full settings page use the same tick mark. The settings page holds only the tracking endpoint, registration key, and tracking-by-default setting; there is no email report.

The extension install view places a direct ZIP download button beside the introduction, followed by custom SVG step icons and responsive setup cards. Its final note explains the public endpoint needed for recipient-side tracking.

The Email Tracking desktop page is the Chrome extension page itself (no local test and no back button): a lavender hero with the purple **Download extension ZIP** button, four numbered install cards, an update callout, a four-card How tracking works flow, and two panels for the tick legend (drawn with the same SVG double check as Gmail) and Good to know notes. The Chrome MV3 companion adds a LeadsGhr control to Gmail, a plain **LeadsGhr tracking enabled** line at the bottom of each compose area (no toggle; tracking follows the popup setting), and gray/purple double ticks with image-load counts for matched sent messages. The extension settings page holds its public HTTPS endpoint configuration and tracked-message list; remote recipient image loads require the optional deployed service described in [Email Tracking](../EMAIL_TRACKING_README.md).

The desktop screens share the Pipeline overview's white surface treatment: light lavender borders, purple accents, and lavender icon or selected-state backgrounds. Dashboard, Pipeline setup, Niche Library, Profile, Email Filtering, and Email Spam Check use these shared colors while retaining their existing layouts. The Crawler and Latest pipelines table keep their open, container-free sections.

The Discovery tools sidebar has separate Email Filtering, Email Validation, and Email Spam Check entries with distinct icons and active states. Email Validation runs a local SMTP RCPT TO probe through Electron. Email Spam Check remains a placeholder and does not claim to perform checks yet.

## Saved crawl runs and exports

Crawl Results saves each filtered row to a dedicated local SQLite run, advances its saved query index after each completed search, and writes a CSV to `C:\LeadsGhr\exports` at stop or completion. The run records selected niches, states, first and last selected state numbers, timestamps, and progress. Pipeline runs additionally save every queued website URL and its page status, so an interrupted run can resume unfinished pages. The CSV includes niche, run date and time (UTC), business, website, phone, location, address, Maps URL, source, and emails. A stopped run can be resumed from Pipeline, Runs, or Exports. Dashboard displays saved runs in one Latest pipelines table with export actions. Exports shows run and file history with entry counts, file sizes and paths, plus re-export actions.

## Crawl Results controls and table

The upper content row uses an icon-only Back button with an accessible label. Contractor results has colored icon controls: Play restarts from the beginning, Pause cancels the current query and retains collected rows, Resume retries that query, and Stop ends the queue. The status line reports the current operation without the redundant completed-count subtitle. A custom results-per-page dropdown and numbered pagination sit at the table's upper right. Long names, URLs, locations and addresses remain on one line with an ellipsis; the complete value is available on hover, and website links remain clickable.

The shared Crawl Results transport controls use `FaPlay`, `FaPause`, and `FaStop` from `react-icons/fa`; Resume retains its existing resume icon. The same shared results component serves both Pipeline and New Search.

The results pagination uses matching chevrons on both sides; the previous-page chevron is rotated to point left.

Crawl Results hides business rows with no website URL by default, even when the Website URL column itself is hidden. In Settings > Preferences > Search > Search result filters, turn on **Show businesses without a website** to include those rows. The preference is saved locally and defaults to off for existing and new users.
